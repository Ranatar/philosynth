# PhiloSynth на Ubuntu 24

Машина для работы: здесь есть Chrome, значит идёт браузерная приёмка, а
с ней исполнимо правило «беседа заканчивается приёмкой». На телефоне это
неисполнимо (`philosynth-termux.md`), поэтому правку исходника ведут
отсюда.

Скрипт поднимает **dev-сборку на 127.0.0.1**. Публичное размещение —
домен, TLS, webhook Stripe, файрвол, копии — отдельный разговор:
`philosynth-hosting.md`.

## Порядок целиком: четыре команды

```bash
git clone https://github.com/Ranatar/philosynth.git ~/philosynth
bash ~/philosynth/deploy/philosynth-ubuntu.sh          # установка
bash ~/philosynth/deploy/philosynth-ubuntu.sh admin    # первый администратор
bash ~/philosynth/deploy/philosynth-ubuntu.sh start    # поднять
```

Команды вводятся в оболочке самой машины, где ставится сервис: у
виртуалки это сеанс SSH (PuTTY), не командная строка хоста.

### Машина за прокси (своя сеть)

Прокси нужен уже первой команде: `git clone` идёт в сеть раньше, чем
появляется скрипт. Поэтому он задаётся на весь сеанс до клона:

```bash
env | grep -i proxy        # прокси уже в окружении? тогда export не нужен
export https_proxy=http://10.0.2.2:ПОРТ http_proxy=http://10.0.2.2:ПОРТ
git clone https://github.com/Ranatar/philosynth.git ~/philosynth
bash ~/philosynth/deploy/philosynth-ubuntu.sh          # возьмёт прокси из окружения и запишет в .env
bash ~/philosynth/deploy/philosynth-ubuntu.sh admin
bash ~/philosynth/deploy/philosynth-ubuntu.sh start
```

`10.0.2.2` — хост, как его видит виртуалка VirtualBox (NAT). `ПОРТ` —
HTTP-вход прокси, не SOCKS: в v2rayN это один из двух локальных портов
(если показан один смешанный — годится он). Прокси на хосте должен
пускать подключения из локальной сети.

Задаётся это **один раз**. После установки адрес живёт в блоке `.env`, и
в новых сеансах `start`, `admin` и повторный `setup` находят его сами,
без `export`; сервер и службы systemd читают его оттуда же. Вместо
`export` можно дать адрес одному прогону — `PHILOSYNTH_PROXY=http://10.0.2.2:ПОРТ
bash ~/philosynth/deploy/philosynth-ubuntu.sh`, — но клону он тогда не
достанется.

Что должно быть в выводе установки:

```
✓ исходящий прокси (из: окружение оболочки): https → http://10.0.2.2:…
✓ API Anthropic достижим через прокси из .env (401 без ключа — так и должно быть)
```

`403` или `ERR` во второй строке — прокси не сработал: проверить порт
(HTTP, не SOCKS) и разрешение подключений из локальной сети. Устройство и
доводы — §1a.

Установка идемпотентна: повторный прогон на готовой машине обязан дать
одни `skip`. Отчёт — в том же виде, что у патч-скриптов доков:
`created / skip / fail`.

## 1. Что ставится

| | Откуда | Зачем |
|---|---|---|
| Node 22 | NodeSource | в репозитории Ubuntu 24 лежит Node 18, проекту нужен ≥ 22.18 (за прокси — ≥ 22.21, §1a) |
| PostgreSQL 16, Redis | apt | база и кэш |
| cairo, pango, libpng, librsvg | apt | системные библиотеки для `node-canvas` |
| Chrome 131.0.6778.204 | части `chrome/` в репозитории (сверка с `chrome/SHA256SUMS`); не сошлись — `@puppeteer/browsers`; в обоих случаях в `~/.cache/puppeteer` | **именно эта сборка**: браузерные тесты писаны под неё, puppeteer-core версию не подбирает |

Chrome ставится в кэш пользователя, а не в систему, — ровно туда, где его
ищут тесты. Если он лежит где-то ещё, наборы его не найдут.

## 1a. Сеть: исходящий прокси своей машины

Это про **свою** машину и **свою** сеть — виртуалку, которая ходит
наружу через прокси хоста. У хостера сеть другая, и там прокси нет
(`philosynth-hosting.md` §3). Поэтому адрес прокси в скрипте не зашит:
скрипт его **находит**, а не найдя — считает, что машина ходит напрямую.

Где ищет, по порядку:

1. `PHILOSYNTH_PROXY=http://адрес:порт` — явно, задаёт и http, и https;
2. окружение оболочки: `https_proxy` / `HTTPS_PROXY`, `http_proxy` /
   `HTTP_PROXY` — порознь, как заданы;
3. настройки apt: `Acquire::https::Proxy`, `Acquire::http::Proxy`;
4. блок прокси в `.env` от прошлого прогона.

`PHILOSYNTH_PROXY=off` убирает блок из `.env`, и сервер снова ходит
напрямую. Годятся только HTTP(S)-прокси: у v2rayN брать HTTP-вход, а не
SOCKS, потому что SOCKS встроенный `fetch` Node не понимает, и скрипт
откажет с объяснением. Из виртуалки VirtualBox (NAT) хост виден как
`10.0.2.2`, и прокси на хосте должен пускать подключения из локальной
сети.

Почему это не «выставить переменные и забыть» — четыре места, где
прокси терялся молча:

| Где | Что было | Что теперь |
|---|---|---|
| сервер → Anthropic, Stripe | встроенный `fetch` Node **игнорирует** `HTTPS_PROXY` без `NODE_USE_ENV_PROXY=1` (проверено на 22.23); генерация шла бы мимо прокси | в `.env` пишется блок `HTTPS_PROXY`, `NO_PROXY`, `NODE_USE_ENV_PROXY=1`; его читают и `start`, и `EnvironmentFile` служб. Флаг понимают Node ≥ 22.21 и ≥ 24, и при прокси скрипт поднимает планку версии с 22.18 до 22.21 |
| `sudo apt-get` | sudo сбрасывает окружение, apt прокси не видел | прокси передаётся под sudo явно |
| `curl` к `127.0.0.1` (health-check) | при `http_proxy` без `no_proxy` запрос уходил в прокси (curl 8.5 петлю сам не исключает), и `start` говорил «молчит» при живом сервере | петля (`localhost,127.0.0.1,::1`) всегда добавляется в `no_proxy` |
| установка Node под root | `$SUDO -E bash` при пустом `SUDO` давал `-E bash` — «command not found» | общая обёртка `as_root` |

http- и https-прокси не склеиваются: прокси, пускающий только CONNECT,
отвечает 405 на http-зеркала apt (поймано прогоном за таким прокси).
Серверу нужен лишь `HTTPS_PROXY`: к Anthropic и Stripe он ходит по https.

Блок в `.env` держится между метками и правится только целиком:

```dotenv
# >>> philosynth-ubuntu.sh: исходящий прокси этой машины
# Только для своей сети. На хостинге блока быть не должно (philosynth-hosting.md §3).
HTTPS_PROXY=http://10.0.2.2:ПОРТ
NO_PROXY=localhost,127.0.0.1,::1
NODE_USE_ENV_PROXY=1
# <<< philosynth-ubuntu.sh: прокси
```

Свой `HTTPS_PROXY`, вписанный в `.env` вне меток, скрипт не трогает.

Итог проверяется отдельным шагом **«Выход к API Anthropic»** (в `setup` и
`status`): тот же `node`, тот же встроенный `fetch`, то же окружение из
`.env`, что у сервера. Ключ при этом не шлётся. `401` значит «дошли»;
`403` обычно значит отказ по стране выхода, то есть прокси нужен, но не
задан или не применился.

Chrome 131 ставится из частей `chrome/` в репозитории, сеть для него
нужна только запасным путём, если части не сошлись с `SHA256SUMS`.
Через прокси это самая долгая загрузка установки (166 МБ).

## 2. Заслон, который стоит до всего остального

Единственность логина и почты держится на `lower()`. Скрипт проверяет
прямой командой, что локаль базы сворачивает кириллицу:

```
✓ локаль сворачивает кириллицу (lower('ИВАН') = 'иван')
```

Если вернулось `ИВАН` — скрипт **останавливается**, а не идёт дальше
молча: иначе два разных человека завелись бы под одним адресом, и
обнаружилось бы это нескоро. На обычной Ubuntu с glibc проверка проходит
всегда; ловит она случай пересозданной базы с локалью `C`.

## 3. Первый запуск базы

Миграций двадцать одна (0000…0020), `drizzle-kit` ведёт их учёт сам, повторный прогон — no-op:

- `0000_initial` … `0003` — основная схема, биллинг, `stripe_customer_id`;
- `0004_admin_audit` — журнал административных действий (беседа 8.1);
- `0005_visibility` — ступень видимости и четыре флага вместо `is_public`
  (беседа 8.6);
- `0006_mail` — подтверждение адреса и сброс пароля: `auth_tokens`,
  `mail_outbox` (беседа 9.1);
- `0007_recommendations` — разобранные рекомендации критики (беседа 10.1);
- `0008_file_genealogy` — дерево генеалогии импортированного файла;
- `0009` … `0013` — происхождение версии, язык интерфейса, метка тезиса,
  замечание и находки сторожа рекомендаций (10.2–12.3);
- `0014_lineage_parent_unique` — одна пара «ребёнок — родитель» (15.1);
- `0015_email_change` — довод смены адреса почты (15.3);
- `0016_plan_editions` — редакции тарифов: `family`, `edition` (15.4);
- `0017_discussion` — обсуждение и рецензии: `synthesis_members`, `comments`,
  `reviews`, `review_revisions`, `review_findings` (16.1);
- `0018_members_notifications` — участники и уведомления: `notifications`,
  `notification_settings`, довод приглашения `member_invite` в `auth_tokens`
  (`synthesis_id`, `member_role`) (16.2);
- `0019_proposals_actor` — предложения изменений и исполнитель: `proposals`,
  `proposal_events`, колонка `actor_user_id` в `element_versions` и
  `generation_log` (беседа 17.1);
- `0020_search_index` — индекс поиска концепций: `synthesis_search`
  (`tsvector` названия, зерна, капсулы и содержания, GIN) и индексы точного
  термина глоссария (беседа 18.1).

Индекс поиска наполняет не миграция, а скрипт — тем же кодом, каким его
держат свежим писатели документа:

```bash
npm run search:reindex -- --missing   # только концепции без строки индекса
npm run search:reindex                # пересчитать все (починка после сбоя)
```

Установочный скрипт зовёт первую команду сам, сразу после миграций; на базе,
обновлённой вручную (`drizzle-kit migrate` без скрипта), её нужно выполнить
один раз — иначе старые концепции находятся только по подстроке названия.

Сидов четыре: 264 шаблона промптов, 27 конфигов, 18 + 29 типов таксономии,
3 тарифа. Все идемпотентны и отчитываются `created / updated / skip / fail`
(сид тарифов с 15.4 — без `updated`: существующие строки он не переписывает,
тарифы после первого посева правятся админкой — вкладка «Тарифы»).

**Тарифы посеются неактивными**, если в `.env` нет `STRIPE_PRICE_*` — это
нормально и скрипт скажет об этом громко. Заведение Prices — `npm run
stripe:create-prices` с вашим ключом Stripe; без него раздел подписки в
интерфейсе пуст. После обновления на 14.1 скрипт запускается ещё раз: он
приводит описание уже заведённого продукта в Stripe к английскому (Д-61),
цены не трогает.

### Обновление уже стоящей службы

```bash
bash deploy/philosynth-ubuntu.sh stop
git -C ~/philosynth pull
(cd ~/philosynth && npm install --no-audit --no-fund)
bash deploy/philosynth-ubuntu.sh            # setup: миграции и сиды, остальное — skip
bash deploy/philosynth-ubuntu.sh start
```

Один раз при переходе на беседу 13.1 (Д-63) — чистка уже сохранённой
разметки: `(cd ~/philosynth && npm run sanitize:stored-html -- --dry)` для
отчёта, затем без `--dry`. Что и зачем — `deploy/philosynth-hosting.md`
§8; скрипт идемпотентен, службу останавливать не требует.

Порядок не случаен. **Сначала `stop`** — из-за схемы. Служба идёт в
dev-режиме (`tsx watch`) и на `git pull` перезапускается сама, то есть ДО
миграций. С миграции `0008` новый код читает
колонку, которой до `setup` в базе нет: сервер, перезапущенный `git pull`,
до миграции отвечает ошибками на всё, что касается синтезов (health при
этом зелёный). Концепции, импортированные до `0008`, древа из файла не
получат — нужно дерево, импортируйте файл заново.

Кэш шаблонов и конфигов прежним доводом за `stop` больше не служит. Он в
Redis бессрочный, и до беседы 12.3 посев его не сбрасывал: служба, пережившая
посев без перезапуска, работала новым кодом на старых конфигах. Теперь сиды
сбрасывают ключи, которые изменили, сами — строка «Кэш реестра: сброшено
ключей — N» в их отчёте. Перезапуск ради кэша нужен в одном случае: сид
сказал «⚠ Кэш реестра НЕ сброшен» (посеву был недоступен Redis), а сервер
запущен; `setup` ловит эту строку и называет команду перезапуска.

**`npm install` — рукой**: `setup` считает зависимости установленными, если
`node_modules` на месте и canvas грузится, и новых пакетов после `pull` не
доставит.

Версии шаблонов, которые вы правили в `/admin/prompts`, посев перекроет новой
версией, если тело в репозитории изменилось; прежняя останется в истории
версий, вернуть её — кнопкой активации.

## 4. Первый администратор — обязательный отдельный шаг

```bash
bash deploy/philosynth-ubuntu.sh admin
```

Роль `admin` в сервисе иначе не получить: ни регистрации администратором,
ни ветки «первый вошедший» нет. Без неё недостижимы `/admin/prompts` и
правка каталогов типов.

Шаг не входит в `setup` намеренно: пароль спрашивается с клавиатуры (и
уходит в скрипт **переменной окружения**, а не доводом — довод виден в
списке процессов и оседает в истории оболочки). Следующих администраторов
назначайте вкладкой «Доступ»: вторым прогоном второго не завести, там
стоит заслон.

## 5. Автозапуск

```bash
bash deploy/philosynth-ubuntu.sh systemd
```

Заводит две единицы — `philosynth-server` и `philosynth-client` — и
включает их. Фоновых работников у PhiloSynth нет, вторая служба здесь
только ради vite.

Оговорка, на которой легко споткнуться: `EnvironmentFile` читает `.env`
построчно и **не понимает кавычек и подстановок**. Значение с пробелом
или со знаком `$` приедет в службу не тем, чем выглядит в файле. Держите
в `.env` простые значения.

Если systemd нет (контейнер, WSL1), скрипт это распознаёт и держит
процессы pid-файлами: они переживут выход из сессии, но не перезагрузку.

**Для публичной машины эти службы не годятся.** Они поднимают dev-режим
(`tsx watch` и vite), а в production сервер идёт собранным —
`node server/dist/index.js`, а клиент отдаётся ставнем как статика.
Единицы для публичного случая — в `philosynth-hosting.md` §4.

## 6. Приёмка

```bash
bash deploy/philosynth-ubuntu.sh accept
```

Прогоняет `typecheck`, `typecheck:scripts`, `check:dotfiles`,
`check-map-04` и `css-parity` — всё, что идёт без браузера. Браузерные
наборы запускаются по одному и требуют живого сервера:

```bash
node tests/test-87-requests2-12.mjs   # витрина и гостевой доступ
node tests/test-86-requests2-14.mjs   # модель публичности
node tests/test-84-requests2-10.mjs   # управление своим содержимым
```

Два предупреждения из накопленных уроков. Прокси vite **зашит на :3000** —
сервер для тестов поднимать только на этом порту. И проверка «в выводе
нет ✗» ложно срабатывает на строке итога «0 ✗»: сравнивайте по шаблону
итога, а не поиском символа.

## 7. Что показывает `status`

```bash
bash deploy/philosynth-ubuntu.sh status
```

Кроме живости процессов отвечает на два вопроса, чей отрицательный ответ
выглядит как поломка, а означает недоделанную установку: сколько
администраторов и сколько активных тарифов. Первое — про недостижимую
админку, второе — про пустой раздел подписки.

## 8. Гостевой вход

После бесед 8.6 и 8.7 без входа открыты `/` (стартовая страница с живыми
карточками и ценами), `/explore` и `/synthesis/:id`. Гостю никогда не
показываются стоимость, токены, логи и запросы к модели — это потолок,
а не настройка автора.

Чтобы адрес был виден с других машин локальной сети, клиент нужно поднять
с `--host`. Для выхода наружу этого **недостаточно и небезопасно** —
смотрите `philosynth-hosting.md`.

## 9. Что беречь

```bash
pg_dump philosynth > philosynth-$(date +%F).sql
```

В базе лежит всё: концепции, версии элементов, родословная, журнал
администратора, балансы и зашифрованные ключи Anthropic.

Отдельно и вне машины сохраните `API_KEY_ENCRYPTION_SECRET` из `.env`:
без него сохранённые ключи не расшифруются, и вводить их придётся заново
всем пользователям.
