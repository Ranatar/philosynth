# PhiloSynth на Ubuntu 24

Машина для работы: здесь есть Chrome, значит идёт браузерная приёмка, а
с ней исполнимо правило «беседа заканчивается приёмкой». На телефоне это
неисполнимо (`philosynth-termux.md`), поэтому правку исходника ведут
отсюда.

Скрипт поднимает **dev-сборку на 127.0.0.1**. Публичное размещение —
домен, TLS, webhook Stripe, файрвол, копии — отдельный разговор:
`philosynth-hosting.md`.

## Порядок целиком: четыре команды

```bash
git clone https://github.com/Ranatar/philosynth.git ~/philosynth
bash ~/philosynth/deploy/philosynth-ubuntu.sh          # установка
bash ~/philosynth/deploy/philosynth-ubuntu.sh admin    # первый администратор
bash ~/philosynth/deploy/philosynth-ubuntu.sh start    # поднять
```

Установка идемпотентна: повторный прогон на готовой машине обязан дать
одни `skip`. Отчёт — в том же виде, что у патч-скриптов доков:
`created / skip / fail`.

## 1. Что ставится

| | Откуда | Зачем |
|---|---|---|
| Node 22 | NodeSource | в репозитории Ubuntu 24 лежит Node 18, проекту нужен ≥ 22.18 |
| PostgreSQL 16, Redis | apt | база и кэш |
| cairo, pango, libpng, librsvg | apt | системные библиотеки для `node-canvas` |
| Chrome 131.0.6778.204 | `@puppeteer/browsers` в `~/.cache/puppeteer` | **именно эта сборка**: браузерные тесты писаны под неё, puppeteer-core версию не подбирает |

Chrome ставится в кэш пользователя, а не в систему, — ровно туда, где его
ищут тесты. Если он лежит где-то ещё, наборы его не найдут.

## 2. Заслон, который стоит до всего остального

Единственность логина и почты держится на `lower()`. Скрипт проверяет
прямой командой, что локаль базы сворачивает кириллицу:

```
✓ локаль сворачивает кириллицу (lower('ИВАН') = 'иван')
```

Если вернулось `ИВАН` — скрипт **останавливается**, а не идёт дальше
молча: иначе два разных человека завелись бы под одним адресом, и
обнаружилось бы это нескоро. На обычной Ubuntu с glibc проверка проходит
всегда; ловит она случай пересозданной базы с локалью `C`.

## 3. Первый запуск базы

Миграций шесть, `drizzle-kit` ведёт их учёт сам, повторный прогон — no-op:

- `0000_initial` … `0003` — основная схема, биллинг, `stripe_customer_id`;
- `0004_admin_audit` — журнал административных действий (беседа 8.1);
- `0005_visibility` — ступень видимости и четыре флага вместо `is_public`
  (беседа 8.6).

Сидов четыре: 261 шаблон промптов, 27 конфигов, 18 + 29 типов таксономии,
3 тарифа. Все идемпотентны и отчитываются `created / updated / skip / fail`.

**Тарифы посеются неактивными**, если в `.env` нет `STRIPE_PRICE_*` — это
нормально и скрипт скажет об этом громко. Заведение Prices — `npm run
stripe:create-prices` с вашим ключом Stripe; без него раздел подписки в
интерфейсе пуст.

## 4. Первый администратор — обязательный отдельный шаг

```bash
bash deploy/philosynth-ubuntu.sh admin
```

Роль `admin` в сервисе иначе не получить: ни регистрации администратором,
ни ветки «первый вошедший» нет. Без неё недостижимы `/admin/prompts` и
правка каталогов типов.

Шаг не входит в `setup` намеренно: пароль спрашивается с клавиатуры (и
уходит в скрипт **переменной окружения**, а не доводом — довод виден в
списке процессов и оседает в истории оболочки). Следующих администраторов
назначайте вкладкой «Доступ»: вторым прогоном второго не завести, там
стоит заслон.

## 5. Автозапуск

```bash
bash deploy/philosynth-ubuntu.sh systemd
```

Заводит две единицы — `philosynth-server` и `philosynth-client` — и
включает их. Фоновых работников у PhiloSynth нет, вторая служба здесь
только ради vite.

Оговорка, на которой легко споткнуться: `EnvironmentFile` читает `.env`
построчно и **не понимает кавычек и подстановок**. Значение с пробелом
или со знаком `$` приедет в службу не тем, чем выглядит в файле. Держите
в `.env` простые значения.

Если systemd нет (контейнер, WSL1), скрипт это распознаёт и держит
процессы pid-файлами: они переживут выход из сессии, но не перезагрузку.

**Для публичной машины эти службы не годятся.** Они поднимают dev-режим
(`tsx watch` и vite), а в production сервер идёт собранным —
`node server/dist/index.js`, а клиент отдаётся ставнем как статика.
Единицы для публичного случая — в `philosynth-hosting.md` §4.

## 6. Приёмка

```bash
bash deploy/philosynth-ubuntu.sh accept
```

Прогоняет `typecheck`, `typecheck:scripts`, `check:dotfiles`,
`check-map-04` и `css-parity` — всё, что идёт без браузера. Браузерные
наборы запускаются по одному и требуют живого сервера:

```bash
node tests/test-87-requests2-12.mjs   # витрина и гостевой доступ
node tests/test-86-requests2-14.mjs   # модель публичности
node tests/test-84-requests2-10.mjs   # управление своим содержимым
```

Два предупреждения из накопленных уроков. Прокси vite **зашит на :3000** —
сервер для тестов поднимать только на этом порту. И проверка «в выводе
нет ✗» ложно срабатывает на строке итога «0 ✗»: сравнивайте по шаблону
итога, а не поиском символа.

## 7. Что показывает `status`

```bash
bash deploy/philosynth-ubuntu.sh status
```

Кроме живости процессов отвечает на два вопроса, чей отрицательный ответ
выглядит как поломка, а означает недоделанную установку: сколько
администраторов и сколько активных тарифов. Первое — про недостижимую
админку, второе — про пустой раздел подписки.

## 8. Гостевой вход

После бесед 8.6 и 8.7 без входа открыты `/` (стартовая страница с живыми
карточками и ценами), `/explore` и `/synthesis/:id`. Гостю никогда не
показываются стоимость, токены, логи и запросы к модели — это потолок,
а не настройка автора.

Чтобы адрес был виден с других машин локальной сети, клиент нужно поднять
с `--host`. Для выхода наружу этого **недостаточно и небезопасно** —
смотрите `philosynth-hosting.md`.

## 9. Что беречь

```bash
pg_dump philosynth > philosynth-$(date +%F).sql
```

В базе лежит всё: концепции, версии элементов, родословная, журнал
администратора, балансы и зашифрованные ключи Anthropic.

Отдельно и вне машины сохраните `API_KEY_ENCRYPTION_SECRET` из `.env`:
без него сохранённые ключи не расшифруются, и вводить их придётся заново
всем пользователям.
