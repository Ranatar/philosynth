# PhiloSynth: публичное размещение под своим именем

Локальный случай — `philosynth-ubuntu.md`. Здесь — то, чем публичный от
него отличается, и отличий больше, чем кажется. Главное из них: у службы
есть **чужие деньги и чужие ключи**, и обе вещи начинают иметь значение
ровно в тот момент, когда адрес становится доступен снаружи.

## 0. Что решить до того, как что-то покупать

### 0.1. Кто платит за генерацию

Две разные службы получаются из одного кода.

**BYO-Key.** Каждый вводит свой ключ Anthropic, служба его шифрует и
тратит чужой лимит. Деньги через вас не идут: ни Stripe, ни тарифов, ни
webhook. Это резко проще во всём, что ниже, — и если вам нужна
«площадка для своих», остановитесь здесь.

**Общий ключ и биллинг.** Ключ ваш, пользователи покупают баланс или
подписку. Тогда вам нужны: настоящий Stripe, публичный HTTPS-адрес для
webhook, возврат денег при сбоях и понимание, что `BILLING_ENFORCE` в
production включается **сам** (`env.ts:80`: при незаданной переменной
берётся `isProd`). Это уже предпринимательство, а не размещение сайта.

Смешанный вариант работает: общий ключ для тарифов, BYO-Key для тех, кто
предпочитает свой.

### 0.2. Что видит гость

После бесед 8.6 и 8.7 без входа открыты `/`, `/explore` и
`/synthesis/:id`. Это решение уже принято в коде, и на публичной машине
оно означает, что **любая концепция со ступенью `full` или `showcase`
доступна всему интернету**, включая поисковые машины.

Потолок гостя зашит и настройкой автора не снимается: стоимость, токены,
логи и запросы к модели гостю не показываются никогда. Но само
произведение — показывается, и авторам стоит об этом сказать до
открытия, а не после.

## 1. Машина

Скромнее, чем кажется: `tsx` в production не нужен, сервер идёт собранным.

| | Минимум | Удобно |
|---|---|---|
| ОЗУ | 2 ГБ | 4 ГБ |
| Диск | 20 ГБ | 40 ГБ |
| Ядра | 1 | 2 |

Диск съедает не код, а база: концепции с версиями элементов, логи
генерации и контекста растут заметно. Логи — главный источник роста, и
их не чистит никто.

Отдельный пользователь, вход по ключу, пароли выключены:

```bash
adduser --disabled-password --gecos "" philos
install -d -o philos -g philos -m 700 /home/philos/.ssh
# ключ в /home/philos/.ssh/authorized_keys, затем в /etc/ssh/sshd_config:
#   PasswordAuthentication no
#   PermitRootLogin no
systemctl restart ssh
```

## 2. Имя и TLS

DNS: `A` на адрес машины, при желании `AAAA`. Дальше ставень — я привожу
Caddy, потому что он берёт сертификат сам и это одна из немногих вещей,
которые можно не делать руками.

```
philosynth.example.org {
    encode zstd gzip

    # Клиент — статика, собранная vite
    root * /home/philos/philosynth/client/dist
    file_server

    # API и живые соединения — на сервер
    handle /api/* {
        reverse_proxy 127.0.0.1:3000
    }
    handle /ws* {
        reverse_proxy 127.0.0.1:3000
    }

    # SPA: всё прочее отдаём index.html
    handle {
        try_files {path} /index.html
        file_server
    }
}
```

Две вещи, которые ломаются молча, если их не сделать:

**`CLIENT_ORIGIN` обязан совпасть с настоящим адресом.** При раскладке
выше (клиент и API на одном домене) CORS вообще не участвует — браузер
видит свой источник. Но стоит вынести клиент на другой домен, и в дело
входит `cors({ origin: env.clientOrigin, credentials: true })`
(`index.ts:46–49`): при расхождении браузер молча не пошлёт cookie
сессии, и вход будет «проходить», не заходя. Переменная дешёвая, держите
её верной с самого начала.

**`SESSION_COOKIE_SECURE=true`.** Иначе cookie уедет без флага `Secure`
(`env.ts:54`) — по HTTPS это работает, но защиты от утечки по HTTP нет.

## 3. Переменные: чем публичный случай отличается

```dotenv
NODE_ENV=production
CLIENT_ORIGIN=https://philosynth.example.org
SESSION_COOKIE_SECURE=true

DATABASE_URL=postgres://philosynth:СИЛЬНЫЙ_ПАРОЛЬ@localhost:5432/philosynth
REDIS_URL=redis://localhost:6379

ANTHROPIC_API_KEY=sk-ant-…            # если служба платит за генерацию
API_KEY_ENCRYPTION_SECRET=…           # 32 байта hex, НЕ менять после запуска

STRIPE_SECRET_KEY=sk_live_…
STRIPE_WEBHOOK_SECRET=whsec_…         # в production ОБЯЗАТЕЛЕН
STRIPE_PRICE_STARTER=price_…
STRIPE_PRICE_PRO=price_…
STRIPE_PRICE_ACADEMIC=price_…
VITE_STRIPE_PUBLISHABLE_KEY=pk_live_…
```

Три отличия от локального `.env`, каждое со своей ловушкой.

**`DATABASE_URL` и `REDIS_URL` перестают иметь умолчания.** В
production `env.ts` требует их явно (строки 34 и 38) и падает при
запуске, а не при первом запросе, — это хорошо, но неожиданно, если
привыкли к локальным умолчаниям.

**`STRIPE_WEBHOOK_SECRET` в production обязателен.** Вне production
пустой секрет означает «подпись не проверяем» (это нужно стенду 8.2); в
production тот же пустой секрет даёт отказ `WEBHOOK_SIGNATURE_INVALID`.
Ловушка в том, что ошибка вылезет не при старте, а при первом настоящем
платеже.

**`API_KEY_ENCRYPTION_SECRET` нельзя менять после запуска.** Им
зашифрованы чужие ключи Anthropic. Смена секрета делает их нечитаемыми
разом и у всех — восстановить нечем, придётся просить всех ввести ключи
заново.

**`VITE_*` вшивается в сборку клиента.** Это не серверная переменная:
поменяли — пересобирайте `client`, иначе в браузер уедет прежнее
значение.

## 4. Развёртывание: три отличия от локального

**Собранный сервер вместо `tsx watch`.** В production идёт
`node dist/index.js` (`server/package.json`, скрипт `start`), а не
`dev:server`. Скрипт `philosynth-ubuntu.sh systemd` заводит именно
dev-режим и для публичной машины **не годится** — служба должна
выглядеть так:

```ini
[Unit]
Description=PhiloSynth server
After=network.target postgresql.service redis-server.service

[Service]
Type=simple
User=philos
WorkingDirectory=/home/philos/philosynth
EnvironmentFile=/home/philos/philosynth/.env
ExecStart=/usr/bin/node server/dist/index.js
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

Второй службы нет: клиент — статика, его отдаёт ставень.

Оговорка про `EnvironmentFile`, на которой спотыкаются: он читает файл
построчно и **не понимает кавычек и подстановок**. Значение с пробелом
или со знаком `$` приедет в службу не тем, чем выглядит.

**Тарифы заводятся до открытия, а не после.**

```bash
npm run build
npm run db:migrate
npm run seed:prompts && npm run seed:configs && npm run seed:taxonomy
npm run stripe:create-prices      # вашим sk_live_, печатает STRIPE_PRICE_*
# вписать напечатанное в .env, затем:
npm run seed:plans
npm run seed:admin                # пароль спросит с клавиатуры
```

Без `STRIPE_PRICE_*` планы сеются неактивными, и раздел подписки будет
пуст — на публичной машине это выглядит как «служба не работает».

**Webhook Stripe** заводится в панели Stripe на
`https://ваш.домен/api/v1/billing/webhook`, события —
`invoice.paid`, `customer.subscription.updated`,
`customer.subscription.deleted`. Выданный `whsec_…` кладётся в `.env`
и служба перезапускается. Без этого подписка остаётся `incomplete`
навсегда: деньги списаны, доступа нет — худший из возможных отказов.

## 5. Файрвол — не «на всякий случай»

PostgreSQL и Redis обязаны слушать только петлю. Redis без пароля,
открытый наружу, — это готовый чужой сервер, а не риск.

```bash
ufw default deny incoming
ufw allow OpenSSH
ufw allow 80,443/tcp
ufw enable
```

Проверьте снаружи, что 5432 и 6379 закрыты, а не поверьте настройке.

## 6. Копии — до открытия, а не после

```bash
pg_dump -Fc philosynth > /var/backups/philosynth-$(date +%F).dump
```

В базе: концепции, версии элементов, родословная, `admin_audit`, балансы
и **зашифрованные ключи пользователей**. Дамп без
`API_KEY_ENCRYPTION_SECRET` восстановит всё, кроме ключей, — храните
секрет отдельно от дампов, но храните.

Проверьте восстановление на пустой базе **до** того, как пустите людей.
Непроверенная копия — это не копия.

## 7. Наблюдение

Смотреть стоит на три вещи, и все три специфичны для этой службы:

**Отказы генерации.** `journalctl -u philosynth -f` плюс таблица
`generation_log`: длинная череда ошибок обычно означает исчерпанный лимит
Anthropic, а не поломку кода.

**Расхождение денег.** Сумма `transactions` против того, что показывает
Stripe. Расходятся — значит какое-то событие webhook не дошло; у Stripe в
панели есть повтор доставки.

**Рост логов.** `context_log` и `generation_log` растут быстрее всего
остального. План их прореживания стоит завести заранее, а не когда
кончится диск.

## 8. Выкатка новой версии

```bash
sudo -u philos git -C /home/philos/philosynth pull
sudo -u philos npm ci --prefix /home/philos/philosynth
sudo -u philos npm run --prefix /home/philos/philosynth db:migrate
sudo -u philos npm run --prefix /home/philos/philosynth seed:prompts
sudo -u philos npm run --prefix /home/philos/philosynth seed:configs
sudo -u philos npm run --prefix /home/philos/philosynth build
sudo systemctl restart philosynth
```

Миграции — до перезапуска, не после: новый код рассчитывает на новую
схему. Сиды шаблонов и конфигов — тоже до перезапуска и ВСЕГДА вместе с ним
(беседа 10.1): они идемпотентны (без изменений — одни skip), но кэш реестра в
Redis бессрочный и посевом не сбрасывается — новые версии служба увидит только
после перезапуска (`warmCache`). Посев без перезапуска оставит новый код на
старых конфигах. Версии, которые вы правили в админке руками, посев
перезапишет новой версией поверх — прежняя останется в истории версий.

Откат назад миграциями не предусмотрен, поэтому дамп снимайте
перед выкаткой, а не после.

Чем кончается перезапуск ДО миграции, видно на `0008_file_genealogy`
(2026-09-21): новый код читает колонку `syntheses.file_genealogy` в каждой
выборке строки синтеза, и до миграции служба отвечает ошибкой «column does
not exist» на всё, что касается синтезов, — при зелёном health-check (он
таблиц не трогает). Миграция одна, `ADD COLUMN` без заполнения: концепции,
импортированные ДО неё, генеалогического древа из файла не получат —
исходный файл сервис не хранит; нужно дерево — импортировать файл заново.

## 9. Грабли публичного случая

**`check:dotfiles` падает на свежем клоне.** Выкладка через веб-интерфейс
GitHub теряет файлы с точкой — `.env.example` приезжает без части строк,
`.gitignore` без части правил. Сторож `npm run check:dotfiles` написан
ровно для этого; на публичной машине прогоняйте его после каждого `pull`,
иначе недостающие строки обнаружатся в самый неподходящий момент.

**Гость и поисковые машины.** Публичные концепции индексируются. Если это
нежелательно — `robots.txt` в статике клиента, но помните, что он ничего
не запрещает, а только просит.

**Один администратор — точка отказа.** Заведите второго сразу после
первого, вкладкой «Доступ»: `DELETE /auth/me` для единственного админа
отвечает 409 (заслон 8.1), но пароль он потерять может.

**Локаль базы.** Единственность почты держится на `lower()`. Проверьте
на боевой базе то же, что проверяет локальный скрипт:
`select lower('ИВАН')` обязан вернуть `иван`.

## 10. Что ещё не решено в самом проекте

Честности ради: несколько вещей публичная машина обнажает, а код их пока
не закрывает.

- **Почты нет вовсе.** Ни подтверждения адреса, ни восстановления
  пароля, ни уведомлений. Забывший пароль восстанавливается только через
  вас и `psql`. При открытой регистрации это станет заметно быстро.
- **Ограничителя регистраций нет.** `rateLimiter` считает запросы, но
  ботов от людей не отличает.
- **Прореживания логов нет** — см. §7.
- **Отвязки родителя в родословной нет** (решение 8.5: «обязанности пока
  нет»).

Первое я бы закрыл до открытой регистрации, остальные — по мере того,
как станут мешать.
