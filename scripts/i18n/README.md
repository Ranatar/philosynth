# Локализация интерфейса PhiloSynth

## Устройство

- `packages/shared/i18n/t.ts` — `tl(key, ru, params?)`: общий для клиента и сервера.
  Второй аргумент — русский текст (он же запасной вариант и источник колонки `ru`).
  Подстановки — `{имя}`; значения — строки, числа, null/undefined/boolean (пустая строка).
  Каталог текущего языка подключается `setCatalogProvider(() => каталог)`; без него —
  русский текст, поведение проекта не меняется.
- `packages/shared/i18n/strings.json` — мастер-таблица: ключ → `ru`, `en`, `de`, `from`,
  `draft`, `params`, `where`, отметки `data` / `static` / `obsolete`. Записи —
  СТОЛБИКОМ: каждое поле на своей строке файла, ключи по алфавиту. Так правка
  одного перевода даёт одну строку в diff, а не всю запись, и файл читается
  глазами. Служебные `from` / `draft` / `params` / `where` остаются в строчку:
  они коротки и правятся инструментами, а не руками. В том же виде пишется и
  выгрузка `i18n:export` для переводчика.
- `scripts/i18n/names.json` — английские смысловые ключи и черновик `en` для
  первичного выпуска. Записи столбиком, поля именованы:

  ```json
  {
    "ns": "common",
    "id": "common.save",
    "ru": "Сохранить",
    "en": "Save"
  }
  ```

  `id` — полный ключ, начинается с `ns.`; `null` — строка не интерфейсная (промпт,
  образец, сопоставитель) и в таблицу не идёт. Разбор строгий: лишнее или
  недостающее поле, `id` вне своего `ns`, повтор пары `(ns, ru)` — отказ с номером
  записи. Переводы на другие языки сюда НЕ пишутся: это словарь имён, а не файл
  переводчика. Переводчик получает выгрузку `i18n:export` — подмножество
  `strings.json` с полями `ru`, `en`, `de`.
  Пространство имён выводится из пути файла: `pages/LoginPage.tsx` → `loginPage`,
  `components/edit/EdgeEditor.tsx` → `edit.edgeEditor`, `server/routes/auth.ts` →
  `server.routes.auth`; строки, встречающиеся в трёх и более местах, — `common.*`.

## Инструменты

```
npm run i18n:init                         # одноразово: опись + names.json → strings.json (--force перезапишет)
npm run i18n:codemod -- --out ../ps-try   # литералы → tl() в копии проекта (испытание)
npm run i18n:codemod -- --in-place        # то же в репозитории
npm run i18n:export -- --lang en,de       # сверка tl() с таблицей + файл для переводчика
npm run i18n:import -- <файл>             # проверка и вливание перевода
npm run i18n:check [-- --strict]          # та же сверка только отчётом, для приёмки
npm run i18n:params [-- --dry]            # говорящие имена подстановок из names.json (params) → таблица
npm run i18n:split [-- --check]           # каталоги рантайма packages/shared/i18n/generated/<lang>.json
```

Порядок применения к коду (беседа 11.2): `i18n:params` → список зеркал с данными
(`MIRROR_EXCLUSIONS` в `i18n-core.mjs`) → сторожа `check:integration` читают русский
аргумент `tl()` (`unTl`) → `i18n:codemod -- --in-place` → `i18n:export` → `i18n:split`.

**params.** Имена подстановок когда-то вывелись из выражений (`value`, `lc2`) — переводчик
их не поймёт. Запись `names.json` с полем `params: ["line", "column"]` задаёт имена по
позициям `{0},{1}` своего `ru`; `i18n:params` накладывает их на строку таблицы того же
ключа (тексты всех языков, `from.*`, ключи `params`). Применять ДО codemod'а.

**split.** Каталог языка — `{ locale, strings }`, вход `setCatalogProvider` (`t.ts`): ключ
попадает, если у него есть перевод на этот язык, включая черновой; `data` и `obsolete` не
попадают; русского каталога нет (ru — второй аргумент `tl()`). Файлы генерируются
(`--check` сверяет, сторож 4aw требует свежести). Сервер читает их из
`server/i18n/locale.ts` по языку запроса; клиент — 11.3.

**Плюралы** (`t.ts`): ICU-подмножество `{n, plural, one {…} few {…} many {…} other {…}}`,
внутри формы `#` — число; форма выбирается `Intl.PluralRules` языка каталога (ru —
one/few/many/other, en/de — one/other; точные `=0`, `=1` допустимы; `other` обязательна).
`i18n:import`/`i18n:check` отвергают перевод с формами не своего языка.

**Какие строки сервера видит опись** (`ui-strings-lib.mjs`, режим `msg`). Не всякий
кириллический литерал, а только сообщение человеку: довод `throw` и `new …Error(…)`,
значение свойств `message` / `error` / `title` и им подобных (`MSG_PROPS`), довод вызовов,
чьё имя кончается на `.json`, `fail`, `decline`, `hint`, `badRequest`, `httpError`,
`apiError` (`MSG_CALLS`). `decline` и `hint` добавлены беседой 12.3 (Д-32): отказ
планировщика рекомендаций `decline(r, "код", "текст")` и часть подсказки `addHint("текст")`
уходят в ответ человеку, но ни одно прежнее правило их не окружало — литерал без `tl()`
проходил `i18n:check`. Сообщение, которое копится в массив голым `push("…")`, опись не
увидит: заведите локальную функцию с именем на `…Hint` / `fail…` либо оберните текст в
`tl()` сразу. Тексты, которые ХРАНЯТСЯ, в `tl()` при записи не оборачиваются: язык
записи — не язык чтения. Если такой текст видит человек, хранится КОД с параметрами, а
фраза собирается при чтении — образец `server/services/recommendation-issues.ts` (причины
сторожа рекомендаций, 12.3, Д-46: `renderIssue` — по литеральному `tl()` на каждый код).
Диагностика владельца в генлоге (предупреждения разбора) остаётся русской и описью не
ловится.

**Утверждение переводов.** en и de УТВЕРЖДЕНЫ 2026-09-29; 27 ключей беседы 12.3 —
десять `server.recommendationPlanner.*` (отказы и подсказка планировщика рекомендаций)
и семнадцать `server.recommendationIssues.*` (фразы находок сторожа) — утверждены
2026-10-06 после вычитки против принятых терминов панели рекомендаций (analysis, ground,
target; Konzept, Adressat, Auswertung, Begründung, Änderung, Beziehungen). Черновиков в
каталогах нет. Новые
ключи беседы получают машинные черновики `i18n:import --draft` (отметка `draft`),
утверждение — задача владельца: `npm run i18n:export -- --lang de --out i18n-request.de.json` (файл со всеми
черновиками), править колонку `de` (не трогая `ru`/`params`/`where`), убрать `de` из
`draft` у вычитанных строк (или оставить текст тем же — совпадающий текст без отметки
считается подтверждением), затем `npm run i18n:import -- i18n-request.de.json` БЕЗ
`--draft` и `npm run i18n:split`. Отметку черновика снимает только вливание человеком;
`--draft` её ставит. То же для `en`.

**export.** Новый ключ в коде → строка таблицы с пустыми переводами; изменился русский
текст → `ru` обновлён, прежний перевод устарел (`from[язык] ≠ ru`); ключа нет в коде →
`obsolete` (`--prune` удаляет). Строки `data` не сверяются. Пока в коде нет ни одного
`tl()`, сверка пропускается. Файл для переводчика — подмножество таблицы того же вида:
нет перевода, устарел (с `prev`: прежние русский и перевод), черновик (`--no-drafts`
не выгружает черновики).

**import.** Отклоняет: неизвестный ключ; русский текст сменился после выгрузки;
подстановки перевода ≠ русским (аргументы плюралов считаются); формы плюрала не своего языка. Новый перевод пишется с `from = ru` и снимает `draft`
(`--draft` — наоборот ставит: для машинного черновика). Тот же текст, что в таблице,
с убранной из `draft` отметкой языка — вычитка подтверждена. Повторное вливание того же
файла ничего не меняет.

**codemod.** JSX-текст → `{tl(…)}`, атрибут → `attr={tl(…)}`, литерал → `tl(…)`,
шаблон → `tl("…", "… {имя} …", { имя: выражение })`; добавляет импорт. Не трогает
файлы-данные (`packages/shared`, сиды БД), исключённые строки, ЗЕРКАЛА С ДАННЫМИ
(`MIRROR_EXCLUSIONS`: `MODE_CONFIG` сервера и его копия `MODE_UI`, ветки подзаголовка
документа, умолчания заголовка — одна сторона пары уходит в промпт/экспорт/сравнение, и
сторожа 4x/4y сверяют русский текст; такие строки остаются литералами с отметкой `data`)
и строки, где подстановка — не примитив (JSX-элемент в переменной): такие перечисляются
для ручной переделки. Отчёт перечисляет `static`-строки (вычисляются при импорте модуля).
Codemod применён к репозиторию в беседе 11.2 (132 файла, 2268 строк).

## Что остаётся ручной работой

- **static** — константы уровня модуля вычисляются при импорте и при смене языка сами не
  обновятся. На клиенте ЗАКРЫТО 11.3: 41 константа → фабрики `const X = (): T => ({…})`,
  вызываемые при отрисовке; `i18n:check` показывает «static в клиенте: 0» и падает в `--strict`,
  если появится новая (сторож 4ax — то же). Остаток вне клиента (9 вызовов на сервере) законен:
  серверные строки собираются в контексте запроса (`runWithLocale`/ALS), а не при импорте — только
  счёт. Отметку `static` в таблице пересчитывает `i18n:export` по коду (`scanStaticCalls`).
  Число в отчёте codemod'а (282) считалось по литералам ДО переписывания и после него не
  воспроизводимо — считать сканером.
- **Машинные значения**, которые codemod обернул в `tl()` по ошибке (имена data-section
  «Структура документа», «Капсула»; операции «удалить»/«перегенерировать» контракта рекомендаций),
  возвращены литералами 11.3 и занесены в `MIRROR_EXCLUSIONS` (запись по тексту); ключи в таблице
  помечены `data`. Правило Фазы 11: значения data-section и сравнения с данными сервера через
  `tl()` не проходят.
- **data** (410 ключей + 38 литералов зеркал `MIRROR_EXCLUSIONS`, состояние 2026-09-28): общие константы и сиды
  БД читают и промпты, и разбор документа; переводятся ПО МЕСТУ ПОКАЗА, а не в самих
  константах — СДЕЛАНО 11.4:
  - `packages/shared/i18n/data.ts` — `displayKey(value)`, `tData(value, params?)`,
    `tDataLoose(value)` (типы каталога в документе — со строчной буквы); значение без
    ключа (пользовательский тип, имя из документа) возвращается как есть;
  - `packages/shared/i18n/generated/data-keys.ts` — генерат `i18n:split`: карта «русское
    значение → ключ» из data-строк таблицы плюс значения файлов-данных, чей ключ потерял
    отметку `data` из-за живого `tl()` (например, «Диалектический» → `common.dialectical`);
    один текст у нескольких ключей — предпочтение `shared.* → data.* → клиент → server.*`;
  - каталоги `generated/<lang>.json` с 11.4 несут и data-строки (иначе `tl()` вернул бы
    русский); правило 11.2 «data — нет» отменено;
  - места показа: метки метода/уровня/глубины, разделы, философы и эпохи, характеристики,
    операции и важность рекомендаций, шаги элементов, режимы (MODE_UI), таксономия и типы
    графа, подзаголовок документа (`subtitleDisplay` поверх нетронутой `subtitleFor`),
    тексты советника совместимости, сообщения `routes/auth` и `validateCharacteristicValue`
    (шаблоны `PASSWORD_TOO_SHORT_TEMPLATE`, `VALUE_ERROR_*` с `{подстановками}`);
  - сторож 4ay `check:integration`; `data.ts` — единственный файл с нелитеральным `tl()`
    (исключён из сканов `i18n-core`).
- Строка с JSX-элементом в подстановке (`synthesis.pauseModal.keyInvalid`) — разбита 11.3 на
  `keyInvalidLead` + элемент + «.» (ключ `keyInvalid` снят `i18n:export --prune`).
