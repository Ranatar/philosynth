# PhiloSynth Service — Уроки и грабли

Всё, что добыто по ходу разработки и годится ВНЕ даты: поведение
окружения, ловушки инструментов, инварианты, из-за нарушения которых
уже ломались беседы. Сведено 2026-09-07 из 33 разделов
«Знания/грабли …» `NEXT-CONTEXT.md`; хроника — в `docs/08-history.md`.

Читать **целиком** перед началом любой беседы (07 §10). Пункты
перенесены дословно; разложены по темам автоматически, по ключевым
словам, и сгруппированы внутри темы по беседе-источнику — если пункт
стоит не в своей теме, его можно переставить без потери смысла.

**Правило пополнения.** Новый урок — сюда, в свою тему, отдельным
пунктом с пометкой беседы. В главу истории урок не дублируется.

   `statement:` (extended protocol) — учитывать в лог-детекторах.
3. `tsc --noEmit <файл>` игнорирует tsconfig — проверять только через
   `-p`/`-b`; check:integration запускать `npm run … -w server`.

### Беседа 12.1 — колонка, значение которой живёт только в HTML

### Беседа 16.1 — курсор по времени, Date в sql``, индекс адресов

1. **Курсор страницы «(created_at, id) > (ts, id)» с датой из JS теряет
   микросекунды**: `timestamptz` хранит `…:39.461287`, `Date` отдаёт
   `…:39.461` — строка курсора проходит условие «>» снова и повторяется на
   следующей странице (smoke-161 B4g). Курсор — id последней строки,
   сравнение кортежем **в PG**: `(created_at, id) > (select created_at, id
   from t where id = $cursor)`.
2. **`sql\`\`` drizzle с `Date` в параметре падает в postgres.js**
   (`ERR_INVALID_ARG_TYPE … Received an instance of Date` при Bind):
   операторы `gt`/`eq` по колонке `timestamp` кодируют дату сами, сырой
   шаблон — нет. Даты — только через операторы drizzle либо строкой ISO.
3. **`findTarget` по одному id не ищет по ключу** — ключа в цели нет; это
   `resolveAddress` падает с id на ключ, потому что адрес несёт оба.
   Сторож переразрешения проверять через `resolveAddress`/`getComment`, а
   «старый id + ключ» — отдельной строкой (5aw).
4. **Выдержка `≤ N` с многоточием — резать до `N − 1`**: `slice(0, N) + "…"`
   даёт N + 1 (A8 смоука поймал).
5. **Новые ключи `common.*` заводить только для строк из трёх и более
   мест** (README i18n): `i18n:export` принимает любой ключ молча, и
   «обязательное поле» в одном сервисе уехало в `common.requiredField` —
   возвращено в `server.discussion.*` с `--prune` (снимает obsolete целиком
   — перед ним убедиться, что других obsolete нет: «удалено 2»).

### Беседа 16.2 — сторожа прежних бесед, читаемые строки, className

1. **Сторож прежней беседы, знающий счёт миграций или enum дословно,
   ломается следующей миграцией**: 4bm «ВОСЕМНАДЦАТЬ (0000…0017», 4bk
   `enum: ["email_verify", "password_reset", "email_change"]` и `0000…001[5-7]`,
   4bk тик работника «maybeMaintain → try processOutbox» — все упали на
   0018 и проходе уведомлений. Ослаблять АЛЬТЕРНАЦИЕЙ (образец 4bl:
   `0000…0016|0016_plan_editions|…`), не снимать; новый сторож пишет свою
   проверку, а старая остаётся историей. Тот же класс, что 09 §4 (16.1)
   для харнессов.
2. **Проверка «нет строк без `emailed_at`» после сводки ловит ПРОЧИТАННЫЕ
   строки**: сводка берёт только непрочитанное, прочитанная до неё строка

### Беседа 17.1 — переименование миграции и журнал

1. **`git mv -k` на НЕотслеживаемом файле молча ничего не делает** (код

2. **Колонка `text({ enum })` без CHECK миграции не требует**: новое

### Беседа 18.1 — полнотекстовый поиск: стеммер, подсветка, фрагменты SQL

1. **Стеммер не сводит все формы слова к одной основе.** Русский snowball:
   «разлом» → «разл», «разломы» → «разлом». Один словарь на документ и
   запрос такую пару не сводит. Работает сумма: документ = лексемы словаря
   языка + `simple`, запрос = объединение разборов всеми словарями — тогда
   основа запроса совпадает с точной формой документа. Следствие для
   `ts_headline`: он разбирает текст ОДНИМ словарём и такое совпадение не
   подсветит — подсветка идёт вторым проходом `simple` поверх первого
   (вложенные маркеры разбирает `splitHeadline`).
2. **Регулярное выражение в `sql\`\`` схемы теряет обратные косые** при
   генерации миграции (`\s` → `s`): в выражениях индексов — POSIX-классы
   (`[[:space:]]`, `[(]`), а не `\s` и `\(`.
3. **Тип фрагмента postgres.js** — `postgres.PendingQuery<postgres.Row[]>`;
   `ReturnType<typeof sql>` берёт последнюю перегрузку (помощник списков) и
   с результатом шаблона несовместим.
4. **Порог `pg_trgm` — настройка сеанса:** оператор `<%` читает
   `pg_trgm.word_similarity_threshold`; менять его — `set_config(…, true)`
   внутри `sql.begin`, иначе значение уедет в пул соединений.
5. **Запасной ход по триграммам шумит на искусственных словах:** слово
   теста, склеенное с общей меткой прогона («терминностьабв» рядом с
   «категориальностьабв»), похоже на соседей общим хвостом. В проверках
   «не находится» брать слова без общей части с остальной фикстурой.
6. **Счёт сторожа вида «в выражении ровно N вхождений»** ломается правкой
   самой функции (`ne(syntheses.visibility, "private")` дважды в
   `pruneInvisible` после ветвления) — правку держать в форме, не меняющей
   счёт (`or(undefined, …)`), либо менять сторож вместе с ней.

   дважды терялись правки теста. Убивать по PID из `ps -eo pid,args | awk`
   с шаблоном, не совпадающим с собственной строкой (`test-11[2]`), и делать
   это ОТДЕЛЬНЫМ вызовом от правок.
2. **Сервер теста со `stdio: "ignore"` слеп**: причина отказа R9 (ничего не
   найдено) была видна только по логу сервера. Писать stdout/stderr сервера в
   файл (`/tmp/t112-server.log`) — всегда.
3. **Подраздельная догенерация пишет `section_key = «graph:Таблица связей»`**
   (2.2), а не `graph`: любой отбор генлога «по разделу» — точный ключ ИЛИ

4. **Байтовая сверка «до/после» через `git worktree HEAD`** с `npm install` в
   самом дереве — надёжный способ доказать, что codemod не сдвинул промпты;
   единственная законная разница `formatCtxLog` — строка «Дата: …» (время
   форматирования) — маскируется, не игнорируется целиком. Дамп-скрипт
   обязан кончаться `process.exit(0)` — redis/почта держат процесс.

### Беседа 11.3 — браузер и язык: контексты, `navigator.language`, preview

1. **Одно хранилище cookie на браузер puppeteer**: гость, выбравший язык,
   оставляет cookie `ui_locale`, и следующий персонаж (вошедший, второй гость)
   открывает страницу уже на этом языке — тесты «без выбора → ru» и «запросов
   каталога 0» падают не по вине кода. Каждому персонажу —
   `browser.createBrowserContext()`.
2. **Headless shell Chrome 131 не читает `--lang`** — `navigator.language`
   остаётся en-US. Язык браузера ставится CDP: `Network.setUserAgentOverride
   { userAgent, acceptLanguage: "ru-RU,ru" }` на странице.
3. **`vite preview` проксирует по `server.proxy`** (`preview.proxy` наследует
   его) — харнесс на сборке поднимается так же, как на dev, только
   `vite build` перед стартом; счётчик запросов по `page.on("request")` с
   регекспом чанков `assets/(en|de)-*.js`.
4. **`page.evaluate`, возвращающий DOM-узел, даёт `undefined`** — проверка
   «кнопка есть» через `find(...)` всегда ложна; возвращать `some(...)`/boolean.
   Клик по кнопке шапки при открытой модалке (`.edit-overlay` накрывает всё)
   — через `el.click()` в `evaluate`, `page.click` упирается в оверлей.
5. **`pkill -f "tsx index.ts"` из инструмента убивает сам инструмент**, если
   образец есть в его командной строке (повтор 11.2): `pkill -f "[t]sx index.ts"`
   — скобки не дают строке совпасть с самой собой.

### Беседа 11.4 — предпосылки харнесса и лимит вызова песочницы

1. **Перед написанием харнесса — одна команда на предпосылки**, не пять

   — в клоне его нет, в песочнице живёт в `~/.npm-global/.../mermaid-cli/

   строки `synthesis_lineage`, а не `syntheses.philosophers`), способ запуска
   (импорт `server/services` из `.mjs` — только через `tsx`, §1.1). Каждая
   такая предпосылка, взятая по памяти другого харнесса, всплывает отдельным
   прогоном.
2. **Селекторы — из кода, не из памяти**: `#modeTabsBar` — панель вкладок

   preview` снимать `kill -9` по PID из `ps -eo pid,cmd` (у него дочерний

4. **Контролируемый input не печатается поверх значения** (повтор §0.6 п.2):

### Беседа 12.2 — как проверять отрисовку графа

1. **3D (WebGL): толщина линии не наблюдаема** — у three.js она 1 при любом
   `linewidth`. Проверять то, чем величина выражена на деле (прозрачность):
   шпион через `evaluateOnNewDocument` на `getUniformLocation` / `uniform1f` /
   `useProgram` / `drawArrays|drawElements` (mode 3, LINE_STRIP) собирает
   значения uniform `opacity` у линий. Headless — `--enable-unsafe-swiftshader`.
2. **2D (d3): данные — `el.__data__`, нарисованное — атрибуты DOM**; клик по
   SVG-элементу — `dispatchEvent(new MouseEvent("click", { bubbles: true }))`.
3. **PNG со случайной раскладкой попиксельно не сверить.** Шпион на
   `CanvasRenderingContext2D.prototype.stroke/fill` пакета `canvas` при вызове
   экспортёра в процессе харнесса даёт толщину, прозрачность, пунктир и цвет
   каждого штриха; по самой картинке — только наличие цвета (пиксель на луче
   «фон → цвет»), порог — от площади наименьшего узла, а не «с запасом»:
   порог 150 при узле в ~110 чистых пикселей мигал.
4. **Мутационная проверка харнесса**: вернуть дефект в код и убедиться, что
   красное — ровно ожидаемое. Проверка, оставшаяся зелёной, пуста (панель
   узла находила «0.00» у метрики соседней панели) — искать по подписи.
5. **Харнесс, привязанный к виду файла**: мок, ставящий метку в абзац по
   образцу («Рекомендация 1:»), на другом файле молча ничего не ставит, и
   тест падает далеко от причины. Запасной путь + проверка, что метка стоит.
   Упавший чужой харнесс сначала прогнать на HEAD без своих правок.
6. **Клиент на сборке в headless — английский** (язык браузера en-US): кнопки
   по русскому тексту не находятся. CDP `acceptLanguage` в КАЖДОМ контексте
   (11.3) — и в харнессе, который про язык ничего не проверяет.
7. **Экспортированный файл в браузере**: `file://` + перехват запросов CDN —
   three r128 и d3 7.8.5 из `node_modules` (приём 4.2); стили проверять
   `getComputedStyle` открытого файла, а не поиском правила в тексте.
8. **Сервер под `vite preview` — только на :3000**: прокси зашит в
   `vite.config.ts`; харнесс сперва убеждается, что порт свободен.

### Беседа 12.3 — гонка слота, итог документа, моки с неполными разделами

1. **Запрос «сразу после WS-сообщения» гонку слота не ловит**: окно между
   сообщением и освобождением слота меньше времени HTTP-запроса. Ловит
   наблюдатель БД: опрос статуса → запрос под гейтом в тот же миг. Проверку
   гонки подтверждать мутацией (вернуть дефект — красное?).
2. **Итог документа сверять с суммой по ВСЕМ обращениям мока.** Проход
   генерации ведёт итог локально и пишет его целиком: побочное обращение,
   внёсшее расход прямо в БД, будет стёрто следующим проходом — и ни один
   тест «таблица составлена» этого не увидит.
3. **Мок, пишущий не все подразделы карты, с 12.3 оставляет пометки в
   генлоге** («модель завершила ответ, не написав подраздел …»). Проверка
   «`parseWarnings` пусты» на таком моке покраснеет; подразделы мока брать
   из `buildSubsectionMap`, а не писать по памяти.
4. **Свойство `label` с кириллическим литералом опись msg-режима считает
   надписью интерфейса** (`MSG_PROPS`): хранимую подпись генлога называть
   иначе (`logLabel`).
5. **Хвост вывода сторожа — одна строка в десятки килобайт**: читать с
   обрезкой по символам (python), `cut -c` режет по байтам посреди буквы.

### Беседа 13.2 — лимитер и пауза в живом харнессе
1. **Лимитер в харнессе — окна минуты и общий Redis**: регистрация и
   вход идут по ключу адреса, и счётчики прошлых прогонов (окно
   `mailLimiter` — час) переживают перезапуск сервера. Перед прогоном —
   `redis-cli --scan --pattern 'rate_limit:*' | xargs redis-cli del`;
   аккаунты заводить ДО потопа и в начале чистого окна (`60000 - Date.now()
   % 60000`); проверять, что отказ — именно того лимитера (у `mail`
   `retryAfter` часовой, общий лимит в новом окне свеж).
2. **Пауза генерации на моке — одним ответом HTTP 500**: `STREAM_RETRY_DELAYS=50`
   → `pre-stream` → ретрай → `status='paused'`, и `paused_state.genParams`
   несёт содержимое родителей — настоящий предмет Д-65, а не вставленная
   рукой строка. Родитель должен пройти `validateConceptForMetaSynthesis`
   (sum/glossary/theses/critique + graph + капсула).
3. **Фикстуры капсулы — без слова «Капсула» в тексте**: `extractCapsuleText`
   снимает ведущее «Капсула», и проверка «капсула несёт „Капсула …“»
   красна при верном коде. Маркер содержимого — своя фраза
   («Содержимое капсулы …»), и он не должен совпадать с текстом ребёнка.
4. **Отчёт на копии БД** — `pg_dump | psql` в `philosynth_copy_132`
   (`createdb -T` не годится: к шаблону подключён сервер); «старые» строки
   вставляются в копию, рабочая база сверяется счётчиком до и после.

### Беседа 14.1 — счёт «до» через worktree, шпион canvas, демоны песочницы
1. **Счёт описи «до правок» воспроизводим машинно**: `git worktree add
   <rev>` + копия текущих `scripts/i18n/*` + символическая ссылка на
   `node_modules` — тест сверяет число и раскладку по файлам с «По факту»,
   а не верит записи.
2. **Текст на картинке проверяется шпионом прототипа**:
   `CanvasRenderingContext2D.prototype.fillText` из `canvas` подменяется на
   время `buildPNG` — все надписи легенды в массиве, кириллица под en
   ловится без OCR; вернуть прототип в `finally`.
3. **Песочница останавливает демоны между ходами**: PostgreSQL и Redis,
   поднятые в прошлом ходе, к следующему мертвы (`ECONNREFUSED` на 5432
   без строки остановки в логе) — перед каждым прогоном `pg_ctlcluster 16

### Беседа 15.4 — strip() сторожей и «/admin/*», экономика в проверках сида
1. **`strip()` сторожей (`/\/\*[\s\S]*?\*\//`) считает `"/admin/*"` в
   кавычках началом блочного комментария** и съедает всё до ближайшего
   `*/` — проверка `billingRoutes.use("/admin/*", requireAdmin)` на
   очищенном тексте «не находила» маршрут. Такие контракты проверять на
   сыром файле (и помнить при любом пути с `/*` в литерале).
2. **Расхождение сида нельзя проверять квотой «+1» у `starter`**: его
   экономика на пределе (`$9.55 × 1.2 = $11.46` при `$9.99`), и +1 синтез
   даёт `fail` экономики ДО чтения строки — не `skip + diverged`. Для
   проверки «строка не переписана» квоту уменьшать или менять название.
3. **Нужен ли `FOR UPDATE`, если внешняя система не откатывается**:
   Price в Stripe заводится до транзакции, поэтому заслон живых подписок
   проверяется дважды — до вызова Stripe (дёшево отказать) и под
   `FOR UPDATE` строки плана (гонка с оформлением подписки); отказ
   транзакции выключает уже созданный Price best effort.
4. **`subscriptionId` ответа `POST /billing/subscribe` — id подписки в
   Stripe (`sub_…`), не UUID строки** (03 §2.10 так и говорит, но харнесс
   первым делом подставил его в `where id = …` → 22P02). Строку искать по
   `stripe_subscription_id`.
5. **Список тарифов на BillingPage грузится своим запросом после клика
   «выбрать»** — `waitForSelector(sub-plans)` не значит, что строки уже
   есть (R4 test-154 один раз получил `[]`); ждать первую строку
   `[data-testid^="sub-plan-"]` (та же грабля, что 09 §9 п.8).
6. **Запертое поле надо показывать**: у `.form-input`/`.form-select`
   исходника нет `:disabled` — `disabled` поле выглядело живым, и только
   снимок браузерного прогона это выдал. Правила для запертых полей — в
   блок беседы; снимок вкладки — часть браузерного теста.

### Беседа 18.1 — проверки поиска: «не находится», стеммер, сбой в живом сервере

1. **Проверка «не находится» рядом с запасным ходом по похожим словам
   хрупка.** «Трансфигурации» находит «трансформации», слово теста с общей
   меткой прогона — соседа с той же меткой. Либо смотреть `match` ответа
   (`fuzzy` — не точная находка), либо брать слова без похожих соседей.
2. **Стеммер поглощает часть опечаток** («rupturs» → «ruptur»): проба
   запасного хода обязана портить ОСНОВУ слова, не окончание, и проверять
   `match === 'fuzzy'`.
3. **«Витрина не ищется по категории» проверяется на категории, слов
   которой нет в капсуле.** Имя первой категории образца стоит в капсуле —
   витрина находится по нему законно. Харнесс подбирает пробы запросом к
   индексу (`capsule_tsv @@ …` и `word_similarity`).
4. **Сбой внутри живого сервера без разъёма в коде** — на уровне базы:
   `ALTER TABLE … ADD CONSTRAINT … CHECK (…) NOT VALID` запрещает новые
   записи, не трогая чтение и существующие строки; снимать в `finally`.
5. **Язык документа для живого теста — вариантом образца:** замена
   `"lang"` встроенного состояния, названия, зерна и нескольких строк по
   всему файлу; разбор и индекс делает сам импорт. Каждая замена обязана
   сработать (иначе харнесс падает на подготовке, а не зеленеет вхолостую).

### Беседа 18.2 — готовность страницы в пробе, JSX под tsx

1. **«Адрес сменился» — не «выдача сменилась».** `history.pushState`
   меняет `location.search` сразу, а роутер v7 отрисовывает новый адрес
   переходом: проба, ждавшая только адреса, читала прежние карточки. Ждать
   нужно признака на странице, что показанное принадлежит текущему запросу
   (у каталога — `data-query` контейнера выдачи, пустой до ответа), и
   сверять его с адресом.
2. **Быстрые действия робота находят гонки, недоступные руке, — и это
   находка, а не шум.** Два действия подряд без ожидания (Enter в поле
   философа, сразу `select` области) показали, что второе считалось от
   прежнего состояния. Чинить код, а не вставлять паузу в пробу.
3. **Компонент клиента под tsx рендерится классическим JSX** — модуль без
   `import React` падает «React is not defined» в `renderToStaticMarkup`.
   В харнессе — `globalThis.React = React` до рендера; файлы клиента ради
   теста не трогать.
4. **Проверка «или пусто» — не проверка.** `ok(!html || …)` с запросом,
   завёрнутым в `catch`, зеленела при опечатке в имени столбца
   (`html` вместо `html_content`). Подготовка обязана упасть, а условие —
   требовать непустого.
5. **Конвейер `… | rev | cut | rev` на строке в несколько килобайт
   кириллицы повис** (песочница). Хвост длинной строки таблицы брать
   срезом в Python.

### Беседа 18.2 (тестовый запрос) — данные пробы против образца

1. **Слово данных пробы обязано отсутствовать в образце.** «Достоверность»
   нашлась в импортированном документе — проверка «гостю не находится»
   покраснела без всякой утечки. Слова брать редкие и проверять их
   отсутствие в образце поиском по файлу.
2. **«В окне» — не для любой строки.** Строка таблицы бывает выше окна
   (длинное определение): проверка «рамка целиком в окне» для неё
   невыполнима, а прокрутка «по центру» прячет её начало. Мерить высоту
   и различать два случая — и в коде, и в проверке.
3. **Прежде чем назвать поведение ошибкой — спросить сервер.** Карточка
   вела к термину при поиске по содержанию: так отвечает маршрут 18.1
   (совпадение в термине несёт его id) — ошибкой было ожидание.
4. **Старый харнесс краснеет не только из-за тебя.** Перед правкой —
   прогон на нетронутом HEAD (worktree с ссылкой на node_modules): он
   отделяет своё от устаревшего в прежних фазах.
5. **Проба, запущенная фоном с `&` внутри вызова, держит вызов до
   таймаута**, если её вывод не отвязан: `( … ) > /dev/null 2>&1 &`.

### Беседа 13.1 — contenteditable внутри dangerouslySetInnerHTML
1. **Живое дерево редактора после команды НЕ чистить**: замена узла под
   кареткой (`<b>` → `<strong>`) сбивает выделение — Chrome уносил набор в
   конец блока (найдено смоуком: «жирно» оказалось после «курсив»). Следы
   `execCommand` снимает ядро при сборке на КЛОНЕ (`readEditorHtml`);
   `styleWithCSS=false`, чтобы были `<b>/<i>`, а не `<span style>`.
2. **Chrome без `defaultParagraphSeparator` ставит `<div>` на Enter, а
   набор после таблицы в конце корня идёт голым текстом** —
   `normalizeBlocks`: `<div>` без класса → `<p>`, строчные пробеги
   верхнего уровня → `<p>`, хвостовые `<br>`, nbsp-заглушки ячеек и
   nbsp набора → пробелы; `prettyMarkup` снимает пробелы ТОЛЬКО рядом с
   блочными тегами (`</strong> <em>` цел — `/>\s*</` стёр бы пробел).
3. **Содержимое редактора — в строку HTML при сборке** (`fillEditable`
   в документе DOMParser), не эффектом после монтажа: приём 1.6b/9.2 без
   второго прохода по DOM. Кнопки панели гасят `mousedown` — фокус и
   выделение остаются в редакторе.
4. **Плашка вложенного подраздела — `contenteditable="false"` плюс
   гашение Backspace/Delete у края соседнего блока, вырезания и drag**:
   одного `contenteditable=false` мало — Backspace в начале следующего
   блока удаляет её целиком.
5. **Родной Enter в конце блока — не ваш друг**: выноску (`div` с классом)
   Chrome раздваивает с тем же классом и без метки, а жирный/курсив у
   края абзаца тянется в новый абзац, и следующий `insertOrderedList`
   оказывается внутри `<strong>`. Enter у края абзаца/подзаголовка/выноски
   — свой: чистый `<p><br></p>` после блока; посреди блока, в `li` и
   ячейках — родной. Каретка «между блоками корня» (`selectNodeContents`
   + `collapse`) — отдельный случай: блок — перед ней, `topBlockOf` его
   не видит.
6. **`insertUnorderedList` в абзаце даёт `<p><ul>…</ul></p>`** — DOM это
   терпит, HTML-разбор нет: сервер закроет `<p>` раньше, и «сохранённое ≡
   увиденному» расходится. Нормализация при сборке выносит блочных детей
   из `<p>`. Проверка «сервер ≡ зеркалу» (readSubsectionSource против
   значения поля) ловит такие вещи — держать её в каждом харнессе
   редактора.

### Беседа 16.3 — ref хозяина и layout-эффекты детей

1. **Ref родительского элемента React привязывает ПОСЛЕ layout-эффектов
   детей**: компонент-сосед, измеряющий DOM хозяина (`AddressMarks` →
   `host.current`) в `useLayoutEffect`, при монтировании видел `null` и
   молча выходил — пометки не появлялись после возврата с вкладки на
   документ, пока не менялась сводка (deps). Измерение — в `useEffect`
   (ref уже привязан), прокрутка по измеренным целям — в
   `useLayoutEffect`. Найдено харнессом test-163 на переходе «→ адрес».
2. **Наложение вместо вставки в `{ __html }`**: любая пометка, вписанная
   в строку раздела, меняет ссылку `{ __html }` при каждой смене сводки и
   переписывает innerHTML (9.2). Кнопки поверх с измерением
   `getBoundingClientRect` относительно `position: relative`-хозяина +
   `ResizeObserver`; проверка в харнессе — маркер-атрибут в теле раздела
   должен пережить добавление комментария.

### Беседа 16.2 — литерал в выражении className

1. **css-parity (C) берёт ВСЕ строковые литералы внутри `className={…}`**:
   `className={pageTab === "document" ? "a" : "b"}` и даже
   `className={cls("document")}` дают «класс document без правил».
   Выносить вызов в переменную до JSX (`const documentTabCls = …;
   className={documentTabCls}`) — литерал уходит из выражения.

### Беседа 17.2 — ожидаемая версия на клиенте, гейты по правам

1. **Номер версии читается ВМЕСТЕ с содержимым, которое человек правит**:
   номер из отдельного запроса (`GET …/versions`) свежее формы — и запись
   пройдёт поверх чужой правки молча. Номер — в DTO чтения, и сервер
   читает номера ДО строк: гонка даёт ложный конфликт, а не потерю.
2. **Правило «каждая запись шлёт ожидание» держит тип, а не память**:
   довод функции API обязателен — забытое ожидание не компилируется;
   сторож проверяет сигнатуры, а не каждый вызов.
3. **Перечитка после конфликта — перенос, а не сброс формы**: нетронутое
   поле берёт текущее значение (чужая правка соседнего поля не
   возвращается к прежнему), тронутое остаётся набранным, поля,
   изменённые другим, названы; запись повторяет человек.
4. **Гейт клиента — по праву, а не по роли**: `capabilities.edit` /
   `manage` / `discuss`; флаг `isOwner` в условии кнопки — ошибка сторожа,
   белый список — с доводом на каждую строку.
5. **Сторож по слову-запрету ловит законные тексты** («перезаписан» в
   предупреждении трансформации): исключение — файлом и с доводом в
   комментарии, а не ослаблением образца.

### Беседа 18.2 — состояние в адресной строке, наложение у термина

1. **Состояние в адресе — один модуль и один сериализатор.** Разбор адреса
   и сборка запроса двумя местами расходятся первым же новым параметром;
   имена параметров адреса берутся у маршрута, а сторож сверяет два списка
   по исходнику разбора сервера.
2. **Роутер применяет адрес переходом.** «Текущее состояние» для
   следующего действия — то, что ЗАПИСАНО в адрес, а не то, что
   отрисовано: ссылку-ref обновляет сама запись; отрисовка перекладывает
   её только при смене объекта параметров (иначе промежуточная отрисовка
   со старым адресом вернёт старое).
3. **Выдача знает свой запрос.** Список, счёт «Найдено N» и условия
   рисуются одной отрисовкой, а запрос стартует эффектом после неё: без
   ключа запроса у результата прежние карточки на кадр стоят под новыми
   условиями.
4. **Чтение адреса — прощающее, запись — строгая.** Ссылку правят руками:
   негодное значение отбрасывается при разборе, а не уезжает на сервер за
   400 на весь каталог.
5. **`ResizeObserver` — отдельным эффектом по хозяину.** Наблюдатель,
   заведённый в эффекте, который зависит от результата измерения,
   пересоздаётся каждым измерением и крутит его без конца.
6. **Ссылка на строку документа несёт и id, и ключ имени.** id нужен там,
   где смотрящий может спросить текущее имя; ключ — гостю и после
   перегенерации раздела, когда id строк новые.
7. **Гейт чтения — по `scope`, а не по владению:** владельцу сервер отдаёт
   `scope: 'full'` всегда; новая ветка `isOwner ||` — ошибка сторожа 4bq.

### Беседа 18.2 (Д-90) — адрес по содержимому ≠ ключ React

1. **Адрес по содержимому не уникален среди соседей.** Две строки с
   одинаковым содержимым дают один адрес — для ветки обсуждения это
   верно, для ключа React — нет. Ключ списка, построенного по DOM
   документа, — адрес плюс номер повтора.
2. **`findIndex` по адресу находит одного.** Подсветку «активного адреса»
   сравнивать по самому адресу у каждого элемента, а не по индексу
   первого найденного.
3. **Мок с повторяющимися строками полезен:** дубликат связи в живом
   документе редок, а харнесс 3.2 показал его случайно (18 строк на 10
   узлов). Красный пункт чужого харнесса — повод разобраться, а не
   «устаревшая проверка».

### Беседа 10.1 — кэш реестра и сиды

1. **Кэш Registry в Redis бессрочный; сиды его НЕ сбрасывают.** Сбрасывают

   старая. Порядок выкатки: миграция → `seed:prompts` → `seed:configs` →
   перезапуск. Тест обновления сидов гоняется при ОСТАНОВЛЕННОМ сервере.
   (С 12.3 — Д-18 — сиды сбрасывают кэш сами, перезапуск после посева не
   нужен: см. «Беседа 12.3» в конце раздела.)
2. **Запасной ход «последняя таблица раздела» — мина замедленного действия**:
   `critique:final_table` при отсутствии «Итоговой оценки» брал последнюю
   `table.doc-table` критики. Новая таблица в конце раздела молча стала бы
   «итоговой оценкой» в контексте других разделов. Добавляя таблицу в раздел —
   `grep` экстракторов контекста на позиционные запасные ходы.
3. **Синхронное обращение к модели допустимо**, когда оно одно, результат
   нужен запросившему сразу, а фоновый вариант потребовал бы WS-сообщения,
   которого текущий клиент не знает (чужой `stream_error` он примет за обрыв
   генерации документа). Слот, квота, журнал и итог — те же, что у фоновых.
4. **Числа в установщиках и руководствах стареют молча**: «шесть миграций»,
   «261 шаблон» в `deploy/*` пережили две беседы (9.1 добавила миграцию,
   10.1 — миграцию и два шаблона); повторилось в 15.3 — «пятнадцать
   миграций» без 0014, 15.1 число не тронула. Добавил миграцию или шаблон —
   `grep -rn 'играци\|шаблон' deploy/ README.md`. И помни про `tsx watch`:
   локальная служба перезапускается на `git pull` сама, раньше посева, —

### Беседа 10.2 — слот и биллинг

1. **Три заслона биллинга у одной операции**: middleware роута, `resolveBilling`
   при взятии слота, счётчик единиц квоты. Бесплатная операция обязана пройти
   ВСЕ три — снять один мало. Проверять человеком без ключа, подписки и баланса
   при `BILLING_ENFORCE=true`, а не подписчиком: у подписчика ошибка молча
   превращается в списанную единицу.
2. **`Math.max(1, n)` в счётчике квоты — скрытая плата за бесплатное**: план из
   одних `delete` стоил единицу с беседы 6.1, и ни один тест этого не видел —
   тесты 6.1 мерили планы с перегенерациями.
3. **Синхронное обращение к модели внутри шага плана** (refine_element) дельты
   не шлёт: своего WS-сообщения у него нет, а чужой `stream_delta` клиент принял
   бы за генерацию раздела. Ход шага клиент видит по `plan_step_started` /
   `plan_step_done` (тот же вывод — 10.1 п.3 о ретрофите).

### Беседа 11.1 — jsonb и кэш реестра при надстройке

1. **`metadata || '{"k": […]}'::jsonb` ЗАМЕНЯЕТ значение ключа, а не дописывает
   массив**: вторая запись предупреждений разбора в ту же строку стирала первую.
   Накопление — `jsonb_set(metadata, '{k}', coalesce(metadata->'k', '[]'::jsonb) ||
   $new::jsonb)`; смоук обязан писать в строку ДВАЖДЫ и сверять объединение.
2. **Правка активного шаблона в БД мимо API не сбрасывает Redis-кэш** (урок 10.1 с
   другой стороны): тест сторожа, снявший правило `UPDATE`-ом, увидел бы прежний
   текст из кэша и зеленел ложно. Перед проверкой — `redis-cli flushall` (или
   `del prompt_cache:<key>`), после восстановления — снова.
3. **Смоук первого запроса — до тестовых запросов, но тест на живом сервере всё
   равно нашёл дефект**, которого чистые функции не видят (п.2 §2 выше): смоук
   проверяет функцию, тест — конвейер. Оба обязательны, замена одного другим не
   работает.

### Беседа 12.3 — успешный ответ, ленивый Redis, ключ строки генлога

1. **Успешный ответ модели — не значит полный.** Сверка «написано ↔
   ожидалось» жила только в ветке обрыва; модель, молча пропустившая
   подраздел, следа не оставляла. Любое «пропуск ловит механизм X»
   проверять на УСПЕШНОМ проходе. С 12.3 — пометка в генлоге раздела, у
   таблицы рекомендаций — свой повтор.
2. **Клиент Redis службы ленивый** (`lazyConnect`, `enableOfflineQueue:
   false`): в скрипте вне сервера первая команда отклоняется, а fail-open
   её глотает — «сброс кэша» молча не происходит. В сидах — явное
   подключение и ЧТЕНИЕ ответа (`Promise<boolean>`), исход — строкой отчёта.
3. **Кэш реестра с 12.3 сбрасывают и сиды** (урок 10.1 п.1 в части порядка
   выкатки устарел). Подсказка при недоступном Redis — «перезапустите
   сервер», а не «повторите посев»: повторный посев даст одни skip.
4. **Строка генлога подраздельного обращения — ключом «раздел:подраздел».**
   С ключом раздела она становится «фактическим размером раздела» для
   оценщика (`loadActualOutputChars` берёт последнюю done-строку без
   двоеточия): после ретрофита перегенерация критики оценивалась по размеру
   таблицы.
5. **Статус, по которому клиент шлёт следующий запрос, пишется ПОСЛЕ
   освобождения ресурса, который этот запрос проверит** (слот операции).
6. **Отказ внешней службы приходит там, где id использован, а не там, где
   он сохранён**: `ensureStripeCustomer` возвращает сохранённый id не глядя,
   «No such customer» отвечает вызов с этим id — там и повтор.
7. **Побочное обращение к модели внутри прохода генерации** обязано вернуть
   свой расход вызывающему: проход ведёт итог документа локально.

### Беседа 12.4 — replay, собранный вручную

1. **Replay состояния при подписке, собранный вручную из полей, теряет
   поля, добавленные позже** (`skipDegrades` 2.2 в replay 1.6b так и не
   попал) и неотличим от живого события. Replay строить тем же
   сериализатором, что живое сообщение, и помечать признаком `replay`
   (Д-50).

### Беседа 12.5 — надстройки над генератами, бережная перерисовка
1. **Третья надстройка над генератом (раскладка тезиса) — по тому же
   образцу**: `apply*` в сиде (идемпотентно, в конец), `strip*` в smoke-12
   (ровно одна, в конце), сторож «генерат без неё, активный шаблон с ней»,
   плюс сверка с разбором (`JUSTIFICATION_LEAD_RE` узнаёт «Обоснование.»
   надстройки) — иначе задание и разбор разойдутся молча.
2. **Перерисовка таблицы из БД бережёт текст ячеек закрытых списков**
   (как заголовки `opts.headers`): прежняя ячейка остаётся, если читается
   в то же значение (`mapThesisType(prev) === db`); столбец ищется по
   заголовку, не по месту. Для этого `locateDocTable` отдаёт `rows`.
3. **Встроенное состояние выгрузки пишет колонки, не константы службы**:
   константа схемы делала legacy-концепцию selective-v1 после круга
   экспорт → импорт без маркера миграции.

### Беседа 13.2 — лимитер до аутентификации, доверие прокси
1. **Middleware, читающее `c.get("user")`, живёт ПОСЛЕ того, кто его
   ставит** — иначе ветка мертва молча (ветка `u:` лимитера с 6.1 не
   работала ни разу; ключом стал хэш любой cookie). Порядок в index.ts —
   инвариант сторожа, а «сессия один раз на запрос» — общий
   `resolveSession`: глобальный проход кладёт `user` (или `null`),
   роутовые middleware переиспользуют `!== undefined`.
2. **Заголовки прокси — один читатель под флагом**: `X-Forwarded-For`
   без `TRUST_PROXY` подделывается прямым обращением к порту; читает их
   только `utils/client-address.ts`, сторож красит любой другой файл;
   `TRUST_PROXY=true` осмыслен лишь с `HOST=127.0.0.1` — сервер
   предупреждает при старте, установщики дописывают переменные в старый
   `.env`.
3. **Правило доступа к содержимому — одной функцией в shared**
   (`metaParentAllowed`), которую зовут все входы (роут, импорт, отчёт);
   предупреждение об отказе — одной фразой на все причины: различать их
   значило бы выдавать состояние чужой концепции по UUID из файла.

### Беседа 14.1 — язык получателя и обработчики вне цепочки Hono
1. **Письмо собирается под языком ПОЛУЧАТЕЛЯ, не запроса**: админ или
   форма сброса на одном языке, адресат — на другом; `runWithLocale`
   вокруг сборки в точке постановки, тело в очереди уже собрано — работник
   почты языка не знает. Регистрация — единственный случай «языка запроса»:
   у нового пользователя выбора ещё нет.
2. **Всё, что живёт вне цепочки compose Hono, контекста языка не имеет**:
   `onMessage`/`onOpen` WebSocket — события сокета, их `tl()` отвечали
   по-русски всем с 11.2; `notFound`/`onError` — напротив, внутри цепочки
   (под `requestLocale`). Новый обработчик вне роутов — явный
   `runWithLocale(user.uiLocale, …)`, и проба живьём, не рассуждение.
3. **Константа модуля с текстом — всегда фабрика**: `tl()` в
   инициализаторе вычислится при импорте по-русски и останется таким
   навсегда; `switch` по ключу вместо `Record`.
4. **Выгрузка-картинка — исключение из правила зеркал ЯВНО**: сторож
   требует `tData` в PNG и запрещает его в HTML/MD/MMD/JSON; «исключение по
   недосмотру» однажды уже дало половинчатый перевод (Д-56).

### Беседа 17.1 — правило в одной функции и вызовы мимо неё

1. **«Правило живёт в одной функции» не значит «достаточно поменять
   функцию».** `editCapability` была одна, но одиннадцать мест звали
   проверку без загрузки участия — правило туда не доходило. Перед
   сменой правила — grep ВСЕХ входов в модуль (и синхронных обёрток), а
   сторожу — запрет обходного входа, а не только форма правила.
2. **«Кто это сделал» — контекст запроса, а не довод функций.**
   AsyncLocalStorage (`actor-context.ts`): ставится в middleware, в
   точках WS и в слоте генерации; писатели читают его сами. Фоновая
   работа (`void executePlan(...)`) контекст наследует, но слот ставит
   его явно — на случай запуска не из запроса.
3. **Предпроверка оплаты стоит ПОСЛЕ проверки права**, иначе чужой
   получает «пополните баланс» вместо 403 — и узнаёт, что путь есть.
4. **Принятие чужого предложения исполняет только общий исполнитель**:
   служба предложений не импортирует ни одной функции правки, статус
   `accepted` пишется в одном месте, ссылки на предложения из тела
   запроса отбрасываются (доверие — флагом вызывающей службы), а заслон
   «устарело» стоит и в принятии, и перед шагом исполнителя — план мог
   пролежать черновиком.

### Беседа 18.1 (Д-87) — общее правило двух путей и цикл импортов

1. **Правило, нужное двум службам, которые зависят друг от друга, —
   в модуль-лист.** Чистку спутников удалённого элемента зовут редактор
   элементов и служба генерации; редактор импортирует службу, а
   `recommendations.ts` (где жила `withIssueTexts`) — тоже. Лист
   `element-satellites` + перенос `withIssueTexts` в лист
   `recommendation-issues` с реэкспортом на прежнем месте — без цикла и
   без правки потребителей.
2. **Сторож, читающий ТЕЛО функции, ломается выносом правила** (4bj искал
   `withIssueTexts([gone, …])` в теле `deleteElement`): при выносе в общий
   модуль сторожу дать читать тело + модуль, а не снимать проверку.
3. **Порт исходника чистил то, что в исходнике жило в DOM.** Гранулярные
   строки (`glossary_terms`, `theses`) — добавление службы; у операции,
   перенесённой из исходника «как есть», проверять, что она делает со
   строками, которых в исходнике не было.

## 9. Стенд биллинга (беседа 8.2)

Оснастка: `tools/stripe-mock.mjs` (мок Stripe REST, вынесен из
test-61; те же шесть маршрутов + `/v1/products`, `/v1/prices` под 8.3),
`tools/stripe-emit.mjs` (отправщик webhook-событий), `tools/dev-billing.sh`
(мок → сервер :3000 → vite :5199, `.env.local` из `.env.local.example`,
заслон на `sk_live_`, `--stop` гасит группы процессов). Продуктовый код
стенд не правит; всё ниже — следствия решений 6.1/6.2, а не дефекты.

1. **Подписка висит в `incomplete`, пока не пришёл webhook.** Сервер
   создаёт Stripe Subscription в режиме `default_incomplete` (6.1): первый
   инвойс ждёт оплаты, клиенту уходит `client_secret` его PaymentIntent.
   Строку `user_subscriptions` в `active` переводит ТОЛЬКО
   `handleStripeWebhook` на `invoice.paid` (он же сбрасывает счётчики и
   ставит период из `lines[0].period`); у подписки, в отличие от
   пополнения, нет confirm-эндпоинта — оплату первого инвойса Stripe
   подтверждает сам и присылает событие. Мок событий не шлёт, оплачивать
   в нём некому, поэтому на стенде «ожидает оплаты» + «Обновить» — норма;
   активирует подписку `node tools/stripe-emit.mjs invoice.paid <sub_…>`,
   отмена по концу периода — `customer.subscription.deleted`. Неизвестный
   `sub_…` → 200 `{ handled:false }` и ничего не меняется — как у
   настоящего Stripe с неинтересным службе событием.
2. **Без `VITE_STRIPE_PUBLISHABLE_KEY` страница уходит в dev-режим.**
   `stripeConfigured()` (client/utils/stripe.ts) читает publishable key
   из env vite; пустой ключ → Stripe.js не грузится вовсе, Payment Element
   не монтируется, и после `POST /billing/topup` кнопка «Подтвердить
   платёж» зовёт `POST /billing/topup/confirm` напрямую (6.2). Сервер
   там перечитывает PaymentIntent у «Stripe» и зачисляет баланс только
   при `status === 'succeeded'` — поэтому мок стенда рождает PaymentIntent
   сразу `succeeded` (`STRIPE_MOCK_PI_STATUS`), а test-61 держит
   `requires_payment_method`, чтобы проверить отказ confirm неоплаченного.
   Задать publishable key на стенде нельзя: Stripe.js пойдёт в настоящий
   `api.stripe.com` с `client_secret` от мока и упадёт.
3. **Чем стенд не равен Stripe.** (а) 3-D Secure и прочие `requires_action`:
   у мока PaymentIntent не проходит состояний `requires_confirmation →
   requires_action → processing`, редиректов SCA нет — ветка
   `redirect:'if_required'` в BillingPage на стенде не исполняется никогда.
   (б) Идемпотентные ключи: настоящий Stripe дедуплицирует POST по
   заголовку `Idempotency-Key`; мок каждый POST считает новым (`pi_N`,
   `sub_N`), клиент 6.1 ключей и не шлёт — повтор запроса на стенде
   даёт второй объект, в Stripe — тот же. (в) Состояния invoice: мок
   отдаёт `latest_invoice` одним снимком, у него нет `draft → open → paid
   / uncollectible / void`, продлений периода, `invoice.payment_failed` и
   `past_due`; `invoice.paid` с любым периодом принимается, проверка
   «новый ли период» — только по `current_period_start` строки БД. (г)
   `customer.subscription.updated` мок не шлёт при `cancel_at_period_end`
   — флаг в БД ставит сам роут `/subscription/cancel`, событие лишь
   подтверждает. (д) Подпись webhook: при пустом `STRIPE_WEBHOOK_SECRET`
   вне production сервер её не проверяет — стенд этим пользуется; в
   production пустой секрет → 400 на любой webhook.
4. **Порты и сироты.** Сервер стенда только на :3000 (прокси vite зашит —
   §4, 5.4); vite на :5199 (как браузерные тесты). Демоны спавнятся
   `setsid` собственными группами и гасятся группой (`kill -- -pid`) —
   иначе tsx/vite оставляют сирот на портах (§4, 1.6/5.1/5.2); чужой
   процесс на порту скрипт не убивает, а называет.
5. **Общий мок в тестах.** test-61/62/71 импортируют
   `createStripeMock({ port, bearer, paymentIntentStatus })` из `tools/`;
   `stripeState` тестов = `mock.state` (pis/subs/customers/requests —
   объединение полей трёх копий: `requests` несёт и `auth`, и `form`).
   Свою копию мока новые беседы не заводят (8.3 — на этом же модуле).
6. **Счётчики мока против персистентной БД.** Пока три копии жили в своих
   тестах и каждая беседа шла в свежей песочнице, никто не замечал, что
   `cus_1`/`pi_1`/`sub_1` рождаются заново в каждом процессе, а
   `users.stripe_customer_id UNIQUE` (0003) их помнит: test-71 после
   test-62 на одной базе падал 500 внутри `ensureStripeCustomer` (23505 на
   `cus_1` от оставленного t62-пользователя). Мок ставит в id метку запуска
   (`pi_<метка>_N`; `idTag`/`STRIPE_MOCK_ID_TAG`/`--id-tag`, пустая — голые
   id); тесты на точные id не завязаны и не должны быть.
7. **Тесты 61/62/71 связаны через общую БД.** test-71 оставляет план
   `starter71` (на нём подписка анонимизированного пользователя — RESTRICT
   истории, убрать нельзя), test-62 требовал «ровно одну строку тарифов» —
   в порядке 71 → 62 падал. Проверки табличных строк — по имени, не по
   счёту; «как до выноса: 109/101/105» верно на любой БД только с этой
   поправкой.
8. **Секция подписки BillingPage грузится своим `GET /billing/subscription`**:
   ожидание «Загрузка… пропала» у секции ключа не гарантирует, что подписка
   отрисована — R8 test-62 флакал на `sub-absent`; ждать нужно каждую
   секцию отдельно. Баланс проверять по `balance-value`: в секции есть
   кнопка «Пополнить на $5.00», и регексп по всему блоку зеленел до confirm.
9. **Демоны песочницы гибнут между ходами и во время длинного хода**: PG
   умер, пока test-82 стартовал (ECONNREFUSED 5432 до первой проверки) —

   `redis-server --daemonize yes --save ''`.
10. **Шаги стенда, зовущие идемпотентные сиды, обязаны читать их отчёт**
